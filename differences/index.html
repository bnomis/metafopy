    Differences from metafor¶

    metafopy follows metafor, and for nearly every function it gives the same numbers, to the digits metafor prints. This page shows where it does not. Each difference has a short summary, the same call in R and in Python with the output of both, and the reason. The R code and the Python code of an example do the same thing, so any difference in the two outputs is the difference.

    Everything that is too small or too specific for an example here is in the detailed notes, grouped by topic. Coming from R lists the rules of the translation.

    The outputs below were captured on 2026-10-21 with R 4.3.3, metafor 5.2-1, emmeans 2.0.4 and lme4 2.0.6, and with metafopy at the commit of the same day. They are a record of that run, not a promise; the tests in src/tests and bin/metafor-audit.sh are what keeps the two in line.

    By design¶

    Differences that follow from Python, not from a gap in the port.

    Names and 0-based indices¶

    R's . in a name becomes _, and every index counts from 0. The study index ids and the position that which.max returns differ by one for that reason; the studies are the same.

    Why: Python counts from 0 and has no . in names. Printed escalc frames still number their rows from 1, as R's do.

    R, metafor 5.2-1

    library(metafor)
dat <- escalc(measure="RR", ai=tpos, bi=tneg, ci=cpos, di=cneg, data=dat.bcg)
res <- rma(yi, vi, data=dat)
res$ids[1:3]
which.max(abs(rstudent(res)$z))

    [1] 1 2 3
[1] 4

    Python, metafopy

    import numpy

from metafopy import datasets, escalc, rma, rstudent

    Fitted models are read-only¶

    res$field <- value changes a fit in R and can add a field that does not exist. A fit in metafopy is a frozen dataclass: use dataclasses.replace(res, field=value) for a changed copy. Assigning to it, or adding an attribute, raises FrozenInstanceError.

    Why: a fit that quietly changes after the fact is a common source of wrong numbers, and R's list-like access is kept for reading (res.tau2, res.beta).

    R, metafor 5.2-1

    library(metafor)
dat <- escalc(measure="RR", ai=tpos, bi=tneg, ci=cpos, di=cneg, data=dat.bcg)
res <- rma(yi, vi, data=dat)
res$tau2 <- 0
res$tau2
res$zz <- 1
res$zz

    [1] 0
[1] 1

    Python, metafopy

    # docs: skip
import dataclasses

    summary() returns text¶

    In R, summary(res) is the fit itself with another print method. In metafopy it is the printed text, as a str that also has the fields of the fit as attributes (s.beta), so printing it and reading from it both work.

    Why: Python has no print methods dispatched on the class of a value; a str subclass gives the same printout without a second fit class.

    Frames from escalc() print like R, selections do not¶

    escalc() returns a pandas.DataFrame subclass that prints as R's print.escalc does: rows numbered from 1, the digits of the effect sizes and variances. Any selection of rows or columns, and pandas operations such as merge, give a plain DataFrame that keeps the attributes (dat.attrs['measure']) but prints the pandas way: rows from 0 and wide frames abbreviated.

    Why: pandas builds a new plain frame for every selection, and R's [.escalc keeps the class. Print the whole frame (print(dat)) to get R's layout.

    digits= where R passes it to print()¶

    R changes the digits of a fit when printing it: print(res, digits=2). A metafopy fit prints with the digits it was fitted with, so pass digits= to rma(); predict(), cumul(), leave1out() and influence() results take a named vector (a dict) as in R, and result.with_digits(...) is the counterpart of print(result, digits=...).

    Why: Python's print takes no arguments. The printed text is the same as R's.

    library(metafor)
dat <- escalc(measure="RR", ai=tpos, bi=tneg, ci=cpos, di=cneg, data=dat.bcg)
res <- rma(yi, vi, data=dat)
print(res, digits=2)

    reporter() is not ported¶

    reporter() writes an R Markdown report of a fit. There is no counterpart: use a Jupyter notebook, which runs the same metafopy code and keeps its output.

    # docs: skip
import metafopy

metafopy.reporter

    AttributeError: module 'metafopy' has no attribute 'reporter'

    Optimiser stop points¶

    metafor maximises some likelihoods with R's nlminb (the PORT library) or optim. metafopy uses SciPy's optimisers, and ports R's optim BFGS and Nelder-Mead only for rma_glmm (CM.EL) and selmodel. PORT is not ported. Where the likelihood has a single clear maximum the two agree to about 1e-4 relative or better. Where it is flat, or has several maxima, the two stop at different points, and the examples below are those cases.

    rma_mv with struct GEN stops at another maximum¶

    On dat.konstantopoulos2011 the REML log-likelihood of ~ year | district has more than one local maximum. R's nlminb stops at a log-likelihood of -32.20462; metafopy's BFGS follows the ridge to its end and finishes higher, at -31.86847, with rho at the boundary.

    Why: different optimiser on the same surface. metafopy's value is the higher likelihood, so it is not the worse fit. For the struct='GDIAG' variant, control={'tau2_init': [0.01, 0.01]} starts metafopy at R's point; see the notes.

    R, metafor 5.2-1

    library(metafor)

    rma_mv with struct UN and a fixed tau2¶

    With one tau2 fixed at 0.5 on dat.berkey1998, metafopy's default fit (a Cholesky parametrisation) stops at a log-likelihood of -1.5004, R at -0.8600. Passing control={'cholesky': False} reaches R's value.

    Standard errors of a location-scale model on a flat scale¶

    With link='identity' the scale slope of this model is near zero, and the Hessian of the log-likelihood is computed by numerical differences that shrink to rounding error. R gives 0.539892 for the first scale standard error and metafopy 0.539621, a relative difference of 5e-4; R's own r=8 and r=4 Richardson depths already differ from each other by the same amount.

    Why: the value is rounding noise in both implementations. metafopy uses depth hessian_r=4 by default, which agrees with R's r=4 to about 3e-6; control={'hessian_r': 8} gives the noisy variant.

    library(metafor)
dat <- escalc(measure="RR", ai=tpos, bi=tneg, ci=cpos, di=cneg, data=dat.bcg)
res <- rma(yi, vi, scale = ~ ablat, link = "identity", data = dat)

    selmodel on a flat likelihood¶

    rma_glmm back-ends and links¶

    rma_glmm(control={'package': ...}) takes 'lme4' (the default), 'GLMMadaptive' and 'glmmTMB', and link= takes the links logit, probit, cauchit, cloglog, log, identity and sqrt. The examples fit dat.bcg with the intercept-only model.

    GLMMadaptive reproduces R's iterates¶

    metafopy's GLMMadaptive back-end is a step-by-step port of mixed_fit (EM stage, then BFGS with R's parscale and re-centred nodes), so it agrees with R to 1e-7 here and usually reproduces where R stops short of the maximum.

    Why: the same algorithm, not just the same objective. The exception is a chaotic BFGS path (UM.RS with mods on bcg), where a 1e-12 change of the start moves the coefficients by about 1e-2; see the notes.

    R, metafor 5.2-1

    library(metafor)
res <- rma.glmm(ai = tpos, bi = tneg, ci = cpos, di = cneg, data = dat.bcg, measure = "OR", model = "UM.FS", control = list(package = "GLMMadaptive"))
c(beta = coef(res), tau2 = res$tau2)

    Fits that fail in R are returned¶

    glmmTMB cannot fit the experimental RR model in R ("Cannot fit ML model"). metafopy returns its maximum-likelihood fit with the same "experimental" warning. The same holds for other measures and models that fail in R; their estimates have no R value to be compared with.

    Why: an error that comes from R's optimiser is not a property of the model, so metafopy does not reproduce it.

    Random numbers¶

    Seeded draws reproduce R¶

    conv_fivenum(method='bc', seed=1) simulates with a port of R's generator, so it gives the same means and SDs as R's set.seed(1); so does gosh(seed=). The values are identical here; only the row labels differ (0-based, from pandas). Without seed, metafopy draws from the stream of set_seed.

    Why: an analysis that reports simulated numbers can be checked against its R original.

    R, metafor 5.2-1

    library(metafor)
dat <- data.frame(n = c(30, 40), mn = c(1, 2), q1 = c(3, 4), md = c(5, 6), q3 = c(8, 9), mx = c(14, 16))
conv.fivenum(min = mn, q1 = q1, median = md, q3 = q3, max = mx, n = n, data = dat, method = "bc", seed = 1, test = FALSE)

    Stricter than R¶

    Places where metafopy raises an error and R passes on, or the other way round.

    A misspelt control entry raises¶

    R matches the names in control against the settings it knows with pmatch and ignores the rest, so a typo does nothing. In metafopy an entry that no function reads raises ArgumentError, so the typo is not lost. Entries that another metafor function reads (optimizer for confint, for example) are ignored as in R.

res$tau2

    fmtx(drop0ifint=TRUE)¶

    R drops trailing zeros only when digits is an integer (2L); a double 2 does not. Python has no 2 against 2L, so metafopy always drops them.

    R's quirks copied on purpose¶

    blup() of a cluster-robust fit recycles quantiles¶

    For a robust(..., club_sandwich=True) fit, R computes the prediction interval of study i with the quantile of coefficient i (modulo the number of coefficients), and warns that the lengths do not match. This is probably a bug in R. metafopy follows it on purpose, gives the same warning, and the two print the same intervals (study 1: -2.4384 to 0.4335; the normal quantile would give -1.5480 to -0.4570).

    R, metafor 5.2-1

    library(metafor)
dat <- escalc(measure="RR", ai=tpos, bi=tneg, ci=cpos, di=cneg, data=dat.bcg)
res <- rma(yi, vi, mods = ~ ablat, data=dat)
rr <- robust(res, cluster=alloc, clubSandwich=TRUE)
head(blup(rr), 2)

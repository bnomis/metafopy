    Differences from metafor¶

    metafopy follows metafor, and for nearly every function it gives the same numbers, to the digits metafor prints. This page shows where it does not. Each difference has a short summary, the same call in R and in Python with the output of both, and the reason. The R code and the Python code of an example do the same thing, so any difference in the two outputs is the difference.

    Everything that is too small or too specific for an example here is in the detailed notes, grouped by topic. Coming from R lists the rules of the translation.

    The outputs below were captured on 2026-10-21 with R 4.3.3, metafor 5.2-1, emmeans 2.0.4 and lme4 2.0.6, and with metafopy at the commit of the same day. They are a record of that run, not a promise; the tests in src/tests and bin/metafor-audit.sh are what keeps the two in line. The audit's R oracle is pinned to R 4.6.2 and lme4 2.1-0 (src/audit/data/r-versions.json); the known differences of the audit were brought up to that pin on 2026-11-03, and an example here that the pinned R no longer shows has been removed.

    By design¶

    Differences that follow from Python, not from a gap in the port.

    Names and 0-based indices¶

    R's . in a name becomes _, and every index counts from 0. The study index ids and the position that which.max returns differ by one for that reason; the studies are the same.

    Why: Python counts from 0 and has no . in names. Printed escalc frames still number their rows from 1, as R's do.

    R, metafor 5.2-1

    library(metafor)
dat <- escalc(measure="RR", ai=tpos, bi=tneg, ci=cpos, di=cneg, data=dat.bcg)
res <- rma(yi, vi, data=dat)
res$ids[1:3]
which.max(abs(rstudent(res)$z))

    [1] 1 2 3
[1] 4

    Python, metafopy

    import numpy

from metafopy import datasets, escalc, rma, rstudent

dat = escalc(measure='RR', ai='tpos', bi='tneg', ci='cpos', di='cneg', data=datasets.load('dat.bcg'))
res = rma('yi', 'vi', data=dat)
print(res.ids[:3])
print(numpy.argmax(numpy.abs(rstudent(res).z)))

    Fitted models are read-only¶

    res$field <- value changes a fit in R and can add a field that does not exist. A fit in metafopy is a frozen dataclass: use dataclasses.replace(res, field=value) for a changed copy. Assigning to it, or adding an attribute, raises FrozenInstanceError.

    Why: a fit that quietly changes after the fact is a common source of wrong numbers, and R's list-like access is kept for reading (res.tau2, res.beta).

    R, metafor 5.2-1

    library(metafor)
dat <- escalc(measure="RR", ai=tpos, bi=tneg, ci=cpos, di=cneg, data=dat.bcg)
res <- rma(yi, vi, data=dat)
res$tau2 <- 0
res$tau2
res$zz <- 1
res$zz

    [1] 0
[1] 1

    Python, metafopy

    # docs: skip
import dataclasses

from metafopy import datasets, escalc, rma

dat = escalc(measure='RR', ai='tpos', bi='tneg', ci='cpos', di='cneg', data=datasets.load('dat.bcg'))
res = rma('yi', 'vi', data=dat)

    summary() returns text¶

    In R, summary(res) is the fit itself with another print method. In metafopy it is the printed text, as a str that also has the fields of the fit as attributes (s.beta), so printing it and reading from it both work.

    Why: Python has no print methods dispatched on the class of a value; a str subclass gives the same printout without a second fit class.

    Frames from escalc() print like R, selections do not¶

    escalc() returns a pandas.DataFrame subclass that prints as R's print.escalc does: rows numbered from 1, the digits of the effect sizes and variances. Any selection of rows or columns, and pandas operations such as merge, give a plain DataFrame that keeps the attributes (dat.attrs['measure']) but prints the pandas way: rows from 0 and wide frames abbreviated.

    Why: pandas builds a new plain frame for every selection, and R's [.escalc keeps the class. Print the whole frame (print(dat)) to get R's layout.

    digits= where R passes it to print()¶

    R changes the digits of a fit when printing it: print(res, digits=2). A metafopy fit prints with the digits it was fitted with, so pass digits= to rma(); predict(), cumul(), leave1out() and influence() results take a named vector (a dict) as in R, and result.with_digits(...) is the counterpart of print(result, digits=...).

    Why: Python's print takes no arguments. The printed text is the same as R's.

    R, metafor 5.2-1

    library(metafor)
dat <- escalc(measure="RR", ai=tpos, bi=tneg, ci=cpos, di=cneg, data=dat.bcg)
res <- rma(yi, vi, data=dat)
print(res, digits=2)
print(predict(res), digits=c(pred=1, ci=3))

    update(evaluate=False) returns a Python call¶

    update(res, method='DL', evaluate=False) returns the call that would refit the model instead of fitting it, as R's does. metafopy's call prints in Python syntax, rma_uni(yi='yi', vi='vi', data=<EscalcFrame>, method='DL'), where R prints rma(yi = yi, vi = vi, data = dat, method = "DL").

    Why: the call is a Python object, and its text is what Python code would run.

    regplot() returns a RegplotResult¶

    metafor has no print method for the object regplot() returns invisibly, so R prints it with print.default: each element under $slab, $ids, $xi, ... $pred, then its attributes. metafopy returns a RegplotResult dataclass with the same elements and the axes drawn on, and prints it as a dataclass; to_frame() gives the elements as a table. ids and order are 0-based, as every index in metafopy, where R's are 1-based (checked 2026-11-07, R 4.6.2, metafor 5.2-1).

    reporter() is not ported¶

    reporter() writes an R Markdown report of a fit. There is no counterpart: use a Jupyter notebook, which runs the same metafopy code and keeps its output.

    # docs: skip
import metafopy

metafopy.reporter

    AttributeError: module 'metafopy' has no attribute 'reporter'

    Optimiser stop points¶

    metafor maximises some likelihoods with R's nlminb (the PORT library) or optim. metafopy uses SciPy's optimisers, and ports R's optim BFGS and Nelder-Mead only for rma_glmm (CM.EL) and selmodel. PORT is not ported. Where the likelihood has a single clear maximum the two agree to about 1e-4 relative or better. Where it is flat, or has several maxima, the two stop at different points, and the examples below are those cases.

    rma_mv with struct GEN stops at another maximum¶

    On dat.konstantopoulos2011 the REML log-likelihood of ~ year | district has more than one local maximum. R's nlminb stops at a log-likelihood of -32.20462; metafopy's BFGS follows the ridge to its end and finishes higher, at -31.86847, with rho at the boundary.

    Why: different optimiser on the same surface. metafopy's value is the higher likelihood, so it is not the worse fit. For the struct='GDIAG' variant, control={'tau2_init': [0.01, 0.01]} starts metafopy at R's point; see the notes.

    R, metafor 5.2-1

    library(metafor)
res <- rma.mv(yi, vi, random = ~ year | district, struct = "GEN", data = dat.konstantopoulos2011)
c(logLik = logLik(res))

    rma_mv with struct UN and a fixed tau2¶

    With one tau2 fixed at 0.5 on dat.berkey1998, metafopy's default fit (a Cholesky parametrisation) stops at a log-likelihood of -1.5004, R at -0.8600. Passing control={'cholesky': False} reaches R's value.

    Why: a worse local maximum of metafopy's BFGS than R's nlminb. For this reason the refits of profile() and of the profile-likelihood confint() of rma_mv fits start at the estimates of the full fit and keep the higher log-likelihood.

    library(metafor)

    rma_mv with struct SPEXP: the range rho and the Hessian¶

    On dat.konstantopoulos2011 the REML log-likelihood of ~ year | district with struct='SPEXP' is flat in the range rho: R's nlminb stops at 0.0559 and metafopy at 0.0560, with the same log-likelihood (-31.91350753) and tau2. With optbeta=True (or lambda1, lambda2, which imply it) the two stop further apart, at 0.0561 in R and 0.0427 here, where metafopy's log-likelihood is 3e-9 higher. Both then drop from the Hessian every row whose entries are within hesstol (1.5e-8). R's curvature in rho is 8.6e-7, so R keeps the row and its Hessian is 3 x 3. At metafopy's point it is 4e-9, so metafopy drops the row and its Hessian and vvc are 2 x 2.

    Why: different optimiser on a flat surface. With rho fixed at R's value metafopy reaches R's log-likelihood. Accepted by decision of the operator (checked 2026-11-05, R 4.6.2, metafor 5.2-1).

    rma_mv with three levels: confint() and simulate() in the fifth digit¶

    The fit rma_mv(yi, vi, mods='~ log(year - 1900 + 1000)', random='~ 1 | district/school') of dat.konstantopoulos2011 agrees with R to about 1e-6 (metafopy's REML log-likelihood is 6e-10 higher). confint() finds each limit with the same Brent root-finder and R's tolerance of 1.2e-4, so the upper limit of sigma^2.2 stops at 0.0626269 in R and 0.0626080 here; with control={'tol': 1e-10} both give 0.0626101223. simulate() carries the coefficients into its draws, which differ by about 6e-7.

    Why: both stop inside the same tolerance, from estimates that differ in the sixth digit (checked 2026-11-05, R 4.6.2, metafor 5.2-1).

    Standard errors of a location-scale model on a flat scale¶

    With link='identity' the scale slope of this model is near zero, and the Hessian of the log-likelihood is computed by numerical differences that shrink to rounding error. R gives 0.539892 for the first scale standard error and metafopy 0.539621, a relative difference of 5e-4; R's own r=8 and r=4 Richardson depths already differ from each other by the same amount.

    Why: the value is rounding noise in both implementations. metafopy uses depth hessian_r=4 by default, which agrees with R's r=4 to about 3e-6; control={'hessian_r': 8} gives the noisy variant.

    R, metafor 5.2-1

    library(metafor)
dat <- escalc(measure="RR", ai=tpos, bi=tneg, ci=cpos, di=cneg, data=dat.bcg)
res <- rma(yi, vi, scale = ~ ablat, link = "identity", data = dat)
res$se.alpha

    [1] 0.53989225 0.01556825

    Refits of a location-scale model that R's optimiser leaves short¶

    confint and permutest refit a location-scale model many times, with one scale coefficient fixed or with permuted rows. Where the scale likelihood is flat, R's nlminb stops some of these refits short, or fails them, and metafopy's optimiser finishes them. Here the lower bound for the scale intercept refits the model with that coefficient fixed. At R's bound, -18.7856, R's refit ends at a log-likelihood of -11.58, below the cut-off of -9.75. metafopy's refit reaches -8.01 by moving the other scale coefficients, so it keeps searching and finds -25.1411. In the same way, permutest skips a permutation whose refit R fails ("did not achieve convergence") and draws the next one, while metafopy keeps it, so the later rows are shifted.

    Why: the refits run on the same likelihood, and metafopy's reach the higher value. A failure or early stop of R's optimiser is not a property of the model, so metafopy does not reproduce it (checked 2026-11-04, R 4.6.2, metafor 5.2-1).

    The fit itself does the same where the scale intercept runs towards tau2 = 0. With mods = ~ ablat + alloc and scale = ~ alloc on dat.bcg, both reach a log-likelihood of -7.0165323, R with the scale intercept at -21.54 and metafopy at -33.71. At R's point the numerical Hessian still inverts, with standard errors of 44591; at metafopy's it does not, so the standard errors and the scale test QS are NaN and the printout leaves out the line "Test of Scale Coefficients". The same holds for optbeta=True on mods = scale = ~ ablat + year, where metafopy leaves out the location test (checked 2026-11-04, R 4.6.2, metafor 5.2-1).

    vif(sim=True) refits the model once per permutation of the data variables, and metafopy draws R's permutations. Where R's nlminb fails a refit, R stores NA and metafopy a value (on mods = scale = ~ ablat + year, iteration 153 after set.seed(1234)); where a scale refit runs towards a boundary, R's stops with a finite Hessian and metafopy's goes further, to where its numerical Hessian is NaN, so metafopy drops the draw. The proportion of simulated VIFs below the observed one then counts a draw more or less (0.6984 in R and 0.6965 here on dat.bangertdrowns2004; checked 2026-11-05, R 4.6.2, metafor 5.2-1).

    R, metafor 5.2-1

    library(metafor)
dat <- escalc(measure="RR", ai=tpos, bi=tneg, ci=cpos, di=cneg, data=dat.bcg)
res <- rma(yi, vi, mods = ~ ablat, scale = ~ alloc, data = dat)
confint(res, alpha = 1)

    Numerical Hessians of selection models and failed refits of rma_mv¶

    Standard errors of selection models come from a numerical Hessian, and R's and metafopy's are computed differently. On the same maximum they agree to about four digits: selmodel(type='beta') of the trim-and-fill fit of dat.bcg has the same log-likelihood (-99.049066667) and delta in both, and the standard error of the estimate is 0.06952 in R (with either of R's optimisers) and 0.06949 here, so its z value and p-value differ in the fourth digit. Where the Hessian is close to singular, R may fail to invert it where metafopy does not: profile() of selmodel(res, type='stepfun') refits each grid point to the same log-likelihood in both, but R reports "Error when trying to invert the Hessian" and gives NA intervals, where metafopy gives values. In the same way, profile() of an rma_mv fit can fail a refit in R (ll is NA) that metafopy completes.

    Why: a numerical Hessian, or a refit that R's optimiser fails, is not a property of the model, so metafopy keeps the inverted Hessian and the completed refit (checked 2026-11-04, R 4.6.2, metafor 5.2-1).

    trimfill of a trim-and-fill result: SE of k0¶

    trimfill() applied to the result of trimfill() ranks the observed and the filled studies by their distance from the pooled estimate. A filled study is the mirror image of an observed one, so in exact arithmetic the two are the same distance away and tie. R's estimate comes from its BLAS matrix products and differs from metafopy's in the last bits, so in R the filled member of each pair is a little closer and ranks first, while here the pair ties exactly and the observed study ranks first. The rank sum of the L0 and Q0 estimators then differs (71 in R, 75 here on dat.bcg), and with it the standard error of k0: 2.4267 in R and 2.5278 here. k0 itself (0) and the estimates agree.

    Why: R's answer depends on which way a rounding error falls, and its BLAS (OpenBLAS) picks its summation kernel by processor, so no fixed order of operations reproduces it (checked 2026-11-05, R 4.6.2, metafor 5.2-1).

    hettest(): the data compared with itself¶

    hettest() computes its bootstrap p-value as the share of statistics that exceed the observed one, and its first sample is the data itself. Both languages compute that sample's statistic apart from the observed one, so the two equal values differ in the last bits and the strict > counts the data against itself by chance. On the odds ratios of dat.bcg with test='lrt' and set.seed(1234) every bootstrap statistic agrees to 3e-15, but R's first one is 4 ulp above its observed value and metafopy's 8 ulp below, so the p-value is 0.928 in R and 0.927 here.

    Why: R's answer depends on which way a rounding error falls (checked 2026-11-05, R 4.6.2, metafor 5.2-1).

    ranef() of an rma_mv fit with transf=transf_ilogit¶

    R's ranef.rma.mv applies transf to each data frame of predicted random effects at once. exp accepts a data frame, but plogis, which transf.ilogit calls, does not, so R stops with "Non-numeric argument to mathematical function". metafopy applies the function to the values and gives what R gives for an element-wise function such as function(x) 1/(1+exp(-x)) (0.4526, 0.4788, 0.5351 for the first schools of dat.konstantopoulos2011; checked 2026-11-05, R 4.6.2, metafor 5.2-1).

    leave1out() under options(na.action = "na.fail")¶

    R's leave1out methods for rma.uni, rma.mh and rma.peto fits name the left-out study (slab) only when na.action is "na.omit", "na.exclude" or "na.pass". Under "na.fail" the result has no slab, and printing it stops in print.list.rma with "argument must be coercible to non-negative integer". The values are the same; metafopy names each row as under "na.omit" (-1, -2, ... for dat.bcg) and prints the table (checked 2026-11-06, R 4.6.2, metafor 5.2-1).
